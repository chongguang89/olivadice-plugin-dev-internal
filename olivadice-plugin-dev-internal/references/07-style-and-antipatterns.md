# 07 代码风格与反模式

## 代码组织

- **按指令拆小函数**：一个指令一个处理函数（`cmd_order`、`cmd_cancel`、`cmd_help`……），消息入口只负责分发。
- **公共能力独立成段**：数据读写、API 封装、绘图、限速发送、权限判断，各自成函数，放在文件下半部分统一管理。
- **禁止把整块业务塞进一个巨型函数**。单函数超过一两百行就该拆。
- 推荐结构：

  ```python
  # ==== 入口与分发 ====
  class Event(object): ...
  def handle_message(plugin_event, Proc, is_group): ...

  # ==== 权限 ====
  def is_admin(uid, ctx): ...

  # ==== 数据读写 ====
  def getData(filename): ...
  def setData(filename, data): ...

  # ==== 工具：API / 发送 / 绘图 ====
  def api_request(...): ...
  def send_forward_message(...): ...
  def load_font(size): ...

  # ==== 各指令实现 ====
  def cmd_xxx(ctx): ...
  ```

- 指令函数统一接收 `ctx` 字典（`templates/main.py` 里已定义），不要一层层传七八个参数。

## 必须防御的地方

这些地方的异常是真实会发生、且必须让用户知道的：

| 场景 | 处理 |
| --- | --- |
| `json.load` / 文件读写 | `try/except`，并按既有逻辑回滚 `.bak` |
| HTTP API 调用 | `try/except` + 检查 `retcode` + `reply` 报错 |
| 绘图（PIL）、字体加载 | `try/except`，字体要能兜底到默认字体 |
| 定时任务线程的循环体 | `try/except`，否则线程静默死亡 |
| 批量操作中的单次失败 | 记录并继续，最后汇总反馈 |

## 禁止的过度防御

以下是"看起来更安全、实际只是噪声"的写法，**不要写**：

| 反例 | 问题 | 正确做法 |
| --- | --- | --- |
| 每个文件操作外面套 `try: ... except Exception: pass` | 静默吞异常，出错后完全查不到 | 只包真正可能失败的地方，且失败要 `reply` |
| 对同一份输入反复校验三四轮 | 冗余，逻辑难读 | 在入口校验一次 |
| 到处 `if x is None: x = {}` | `getData` 已经保证返回 dict | 只在确有可能为空的地方判断 |
| `if not isinstance(data, dict): data = {}` 之类的无意义兜底 | 掩盖真实的数据错误 | 让错误暴露出来 |
| 永远不会走到的分支（"以防万一"） | 死代码 | 删掉 |
| 大段「# 这是一个函数，用于……」的自解释注释 | 噪声 | 只注释**为什么**这么做，不注释在做什么 |
| 给不可能为空的变量加 `if` 保护 | 噪声 | 不写 |
| 把 `time.sleep()` 包在 `try` 里 | 无意义 | 直接写 |

判断标准一句话：**这个地方真的会失败吗？失败了我需要知道吗？** 两个都"是"才写防御。

## 静默 return 规则

无关的消息（不是本插件的指令、不在本插件负责的群里）**直接 `return`，不产生任何回复**。群里其他机器人/其他插件在跑，插嘴会造成骚扰。

只有"用户主动触发本插件、但条件不满足"的情况才回复（例如权限不足、数据不存在），并且文案要说清楚为什么。

## 文案与命名

- 回复文案口语化，可以带语气词（「噢」「啦」「～」）和固定收据符号，符合所在群的气氛。
- 报错文案要给出下一步（"请联系骰主"、"请稍后重试"），不要只丢一个异常字符串。
- 变量/函数用英文小写下划线；模块级常量全大写（`PATROL_TIMES`、`MAX_IMAGES_PER_ORDER`）。
- 权限列表、时刻表这类配置放文件顶部，别散落在函数里。

## 交付前扫一遍

- 全文 `print(` 应当为 0 处。
- 全文 `import schedule` 应当为 0 处。
- 每个循环发送的地方都应该有 `sleep`。
- 每个 `try/except` 后面都应该有 `reply` 或明确的中断逻辑，而不是 `pass`（线程循环体除外）。
- 头部注释的「版本」「更新日期」「更新日志」都已填写。
